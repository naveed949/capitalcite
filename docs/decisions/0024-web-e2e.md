# 0024. Browser proof and a pinned proxy

Date: 2026-10-23

Status: Accepted

Someone analysing bank financials asks a question on the page and
needs a cited span, a refusal, a gated tool, or a cancel that
actually stops the run. PR #42 shipped the page. This record is why
the proof is Playwright against `next start`, why Chromium is the
only CI browser, why the proxy pins the model and caps the body, and
how cancel reaches uvicorn.

## Playwright, not Cypress, not Selenium

The page is one screen. The client is already `fetch` plus a
`ReadableStream`. `verify-browser.mjs` already imports `playwright`
and launches Chromium. Playwright is that same library with a
runner, a trace, and an HTML report. Adding it as a `web`
devDependency makes a clean clone reach the verify browser step.

Cypress is a second runner and a dashboard. The repo is public and
CPU-only. A paid service is out of scope. Selenium is a driver
stack for the same Chromium we already launch. It does not buy a
better assertion on a citation chip or a cancel.

## Chromium only in CI

The product path is Chromium. Firefox and WebKit would double the
browser cache and the job time without a second supported engine.
CI caches `~/.cache/ms-playwright` so the install is not a cold
download on every PR.

## `next start`, not `next dev`

`next dev` is a compiler. It can buffer a stream. ADR 0020 already
set `compress` false for that reason. `next start` is the server a
person runs after `next build`. The `e2e` job and `verify.sh` start
that server so a green check is the production page, not the
toolchain.

## Cancel across SSE, the proxy, and the server

The user clicks Cancel. `useAsk` aborts the `AbortController`.
`askStream` stops reading. `sseFrames` calls `reader.cancel()` so
the response body is torn down. The Next proxy forwards
`request.signal`. FastAPI watches `http.disconnect` before it peeks
the first event, so a cancel during retrieve is observed. The
request task is cancelled. The page shows `Cancelled`. The e2e spec
also reads the API log for `ask stream cancelled by client`. A
UI-only abort that never reaches uvicorn is not a pass.

A malformed frame yields a transport fault first. Then the
controller aborts. That order keeps the session `failed`, not
`Cancelled`.

`CAPITALCITE_TEST_SLOW_RETRIEVE_MS` sleeps only for the cancel
question, and only when the e2e job sets it. Production stays at 0.

## Server-side model pin

The browser used to send `model`. The proxy forwarded it unread. A
public page that posts `openai` would spend a key the operator did
not grant that browser. The Next route now writes `model` from
`ASK_MODEL` on the Next process, default `fake`, and overwrites the
client field. The demo label still reads the same env. The API
still accepts `model` from curl and MCP.

## Body cap at both layers

The proxy used to forward the unread body. A 60 MB JSON question
was a legal `AskRequest` (`min_length=1` only). The proxy now
reads at most 16 KiB and returns 413. `AskRequest.question` has
`max_length=8000` and returns 422. The proxy cap is bytes of the
HTTP body. The API cap is characters of the question. A caller
that bypasses Next still cannot park a filing-sized string in the
model prompt.

An unreachable API used to throw in the route handler. The proxy
catches that fetch and returns 502 with
`{"detail":"upstream unavailable"}`. The body has no traceback.

## Gate deny without a production hack

The e2e job sets `GATE_POLICY` to a valid file whose `tools` map
is empty. The gate already denies an unknown tool. The timeline
shows `unknown_tool`. The shipped `tools.json` is unchanged.

## Node 22

Playwright and Next 16 need Node 22.19 or newer. `.nvmrc` is `22`.
`web/package.json` `engines.node` is `>=22.19.0 <23`. CI
`setup-node` reads `.nvmrc`.
